Best practices

All documentation pages

Fuse stays fast and exact when the working tree stays small and each agent checks its own paths. This page lists the practices that keep it that way when agents share a repository.

This page is for a developer or an orchestrator who runs agents with Fuse in one repository.

After reading it you can keep checks fast and answers exact: commit finished work, isolate workers with sessions, write shadow-safe tests, exclude template trees, keep analyzers fast, keep files small, restore after package changes, and act on each fuse note.

Keep the working tree small #

Commit finished work before you start a large wave of agents, and commit each finished wave before the next one. Keep uncommitted files well under 500. Past 500 changed files a check skips its kept answer, the earlier result it would reuse without checking again, so every check starts from scratch and takes longer. HEAD is the commit checked out, and the working tree is the files on disk: the count that matters is how far the disk has moved from HEAD.

Run fuse status to read the counts before a large commit: changed files, changed C# sources, and the tree stamp the command line checks carry (Commands). When the tree is large, run fuse build for the complete answer (Commands, Limits).

Give each worker its own paths #

A session is one agent's run. Whether a subagent is a session of its own depends on its harness (Subagents and parallel agents). A worker that writes from outside any harness, such as a program or a generator, is credited to no session, so register it before it starts:

fuse session begin worker-3 --paths "src/Workers/Third/**" "src/Shared/**"
FUSE_SESSION=worker-3 fuse check

List live registrations with fuse session list, have each worker verify with fuse gate --session <name>, and end the registration with fuse session end <name> when the worker stops. The gate checks only the files whose registered patterns match that session, plus what that session's declaration changes reach anywhere in the repository. It never marks the session stopped: only the stop hook does. Judges and workers explains the flow, and Commands and Commands list the forms.

A worker that runs Fuse itself sets FUSE_SESSION to its name instead of registering. An orchestrator sets FUSE_SESSION=judge for its own integration checks after the workers finish, so the stop hook and the attribution never credit a worker's errors to the judge. Commit between waves so each wave starts from a small tree (Keep the working tree small).

Anchor test paths with CallerFilePath #

A test that walks parent directories from AppContext.BaseDirectory or Assembly.Location resolves those paths against the shadow copy, the copy of the build output a run without MSBuild works from, and may read the wrong file. Such a project runs from its build output instead of the faster shadow copy.

Find the repository root with [CallerFilePath] beside the test source instead of walking up from the running assembly:

static string RepoRoot([CallerFilePath] string path = "")
    => Path.GetFullPath(Path.Combine(Path.GetDirectoryName(path)!, "..", ".."));

A run from the copy is labeled from shadow copy (without MSBuild), so you can see which form ran. How it works explains the runs, and Limits lists what a run from the copy does not see.

Exclude template and fixture projects #

Put generated or vendored trees that Fuse should never evaluate in a repository-root .fuseignore file. It holds gitignore-style path patterns and # comments, and nothing else. It removes the matched paths from project discovery and change tracking. Fuse never writes it. fuse init is the only setup a repository needs; .fuseignore is optional and only excludes paths.

Template and placeholder projects need no entry: a project under a .template.config tree is skipped, and so is an unrestored project file that holds placeholder tokens. Such files are never treated as changes. Commands lists what discovery skips, and Limits lists the scope a check covers.

Keep analyzers fast #

Keep analyzers incremental: an analyzer whose compilation start takes 150 ms or more counts as compilation-wide and runs once per project per check instead of once per file. Analyzers get at most 60 seconds per check. Past that the check reports every compiler error, the analyzer errors that finished, and how many analyzers did not finish.

Editing a file listed as an MSBuild AdditionalFiles item, for example AnalyzerReleases.Unshipped.md, reaches the analyzers on the next check, without restarting the engine. Run fuse build for the full analyzer answer, which runs every analyzer. How it works explains the analyzer run, Limits lists what a check leaves out, and Troubleshooting shows how to find a slow analyzer.

Keep C# files small #

A change inside one method body is checked in the edited file, while a declaration change loads the dependent projects. Keep one type per file and split large classes, so a worker's paths and a check's change cone stay small. A changed non-generated C# file of 1,500 lines or more also prints an advisory (Read each fuse note).

How it works explains how a declaration change reaches dependents, and Architecture maps that behavior to the code.

Restore after package changes #

After dotnet restore, or a build that restores, updates a project's obj/project.assets.json, the next check reloads that project. When a project file declares a package its assets file lacks, the check reports that a restore is needed instead of checking against stale inputs. Fuse never restores on its own: run dotnet restore and check again. How it works explains how projects load, and Messages and fixes shows the restore report.

A change to Directory.Packages.props, a project file's package or project references or build properties, or Directory.Build.props, Directory.Build.targets or global.json selects the dependent test projects. Comment-only edits select nothing. How it works explains the selection.

Read each fuse note #

A command line command prints at most one fuse: note: line, naming the decided limit or practice that slows you down. fuse status lists every active note, and fuse gate --json carries them as advisories. Hooks never print notes, and a note never changes an exit code.
