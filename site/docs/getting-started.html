Getting Started

All documentation pages

Set Fuse up in your .NET repository in two commands, then see what your agent will get from it.

This page is for a developer with a .NET repository and an AI coding agent.

After it your agent uses Fuse on its own. Connect your agent shows what was set up for your harness.

Requirements #

  • The .NET 10 SDK. Your projects can target older frameworks.
  • A git repository with at least one commit. Fuse reports only what changed since the last commit.
  • Restored projects. Fuse never runs dotnet restore itself; if a project is not restored, it tells you the command to run.

1. Install Fuse #

dotnet tool install -g Fuse

This puts fuse in ~/.dotnet/tools (%USERPROFILE%\.dotnet\tools on Windows). That folder must be on your PATH and on your agent's, because the hooks run fuse.

2. Set up your repository #

In the root of your repository:

fuse init
wrote .claude/settings.json
wrote .gitignore
fuse: hooks registered; after each edit your agent gets the compiler errors the edit introduced, `dotnet test` runs the affected tests, and `dotnet build` prints only its errors

fuse init finds the agent tools your repository uses, such as .cursor/ or .gemini/, and adds Fuse's hooks to each. With none found, it sets up Claude Code. Run it again at any time; it only replaces its own entries. That is the whole setup.

The first Fuse command in a repository starts a background process that loads your solution. It stays running until it has been idle for 30 minutes, and every later command and hook reuses it.

3. Check an edit #

Rename a public method that another project calls, then run:

fuse check

Fuse reports every caller the rename broke, in every project. For example, renaming Calc.Add in a library called by App and Lib.Tests prints:

App/Program.cs(3,30): error CS1061: 'Calc' does not contain a definition for 'Add' and no accessible extension method 'Add' accepting a first argument of type 'Calc' could be found (are you missing a using directive or an assembly reference?)
  removed: public int Add(int a, int b)
Lib.Tests/CalcTests.cs(6,54): error CS1061: 'Calc' does not contain a definition for 'Add' and no accessible extension method 'Add' accepting a first argument of type 'Calc' could be found (are you missing a using directive or an assembly reference?)
  removed: public int Add(int a, int b)
fuse: 2 error(s) introduced in 2 file(s) (App, Lib.Tests); Lib declarations changed, 2 dependent project(s) checked
  • Only errors your change caused are listed. Errors that were already in the last commit are left out.
  • The indented line under each error names the change that caused it, here the removed Add.
  • The exit code is 0 when there is nothing to fix, 1 when there is, and 2 when Fuse could not answer.

A change inside a method body cannot break other files, so Fuse checks only the edited file and answers faster.

4. Run the affected tests #

Undo the rename, change a method body so that one of its tests fails, and run:

fuse test
FAILED Lib.Tests.CalcTests.Multiplies
  Assert.Equal() Failure: Values differ
  Expected: 6
  Actual:   7
  at Lib.Tests.CalcTests.Multiplies() in Lib.Tests/CalcTests.cs:line 9
fuse: 1 failed, 0 passed in 2.8 s; ran 1 test(s) affected by your changes out of 2; fuse test --all runs everything; without MSBuild

Fuse ran only the tests that reach the changed code, and printed only the failure. without MSBuild means it skipped the rebuild: only .cs files had changed, so it used the code it already had compiled. fuse test --all runs every test.

Undo your test edit with git restore on the file when you are done.

5. What the agent gets #

You ran the commands by hand. Your agent does not need to: the hooks run them for it.

  • After each edit the agent gets the output of fuse check for that edit. A clean edit prints nothing.
  • When the agent runs dotnet build or dotnet test, the hook changes it to fuse build or fuse test. Cursor and GitHub Copilot CLI cannot do this; there the agent can call fuse directly.
  • Before the agent finishes, Fuse checks all its changes and sends it back once if errors remain.

To see exactly what Claude Code's agent would receive after an edit, pass the hook the JSON Claude Code sends (bash):

echo '{"tool_input":{"file_path":"Lib/Calc.cs"}}' | fuse hook claude post-edit

It prints the same errors as fuse check, or nothing when the edit is clean.
