Fuse Documentation

All documentation pages

Fuse makes dotnet build and dotnet test faster for AI coding agents. After each edit, the agent learns which compiler errors it caused and which tests it broke, in a fraction of the time and output.

This page is for anyone new to Fuse: a developer setting it up for an agent, someone deciding whether to rely on it, or a contributor.

After reading it you know what Fuse does for an agent, what it costs, the few words the rest of the documentation uses, and which page answers your question. To try it, go on to Getting started.

Why Fuse exists #

An AI agent checks its work by running dotnet build and dotnet test, often dozens of times in one task. That is slow and noisy:

  • Every build starts from scratch. The median build took 1.14 s to 6.45 s on the benchmark repositories, and the agent waits for it after every edit.
  • A build lists every error. Errors that were there before the agent started show up too, and the agent has to guess which ones are its own.
  • A test run runs every test and prints the passing ones too.
  • Subagents make it worse. Several builds at once use a lot of memory and fail on each other's locked files in obj and bin.

Fuse is built for agents, not for people. Its output is only what an agent needs to act on, and the agent's tool runs it automatically.

What your agent gets #

Fuse keeps your solution loaded in a background process, the engine, and compares your files with the last commit. After an edit:

  1. The agent edits a filefor example, it renames Calc.Add to Plus.
  2. The hook runs Fusewith the name of the edited file.
  3. Fuse checks the changein the edited project and in every project that uses Add.
  4. The agent reads the resultthe two callers that broke, or nothing when the edit is clean.
  • Faster checks. 7.2x to 22.6x faster than dotnet build on three open-source repositories (Benchmarks). A change inside a method body is checked in the edited file only.
  • Only affected tests. 1.4x to 4.4x faster than dotnet test. When only .cs files changed, tests run without a rebuild.
  • Only new errors. Errors that were already in the last commit are not reported.
  • Breaks in other projects. Each broken caller is listed with the change that broke it.
  • Short output. At most 20 errors or 10 test failures, plus one summary line. Nothing when the edit is clean.
  • Made for subagents. All agents in a repository share one engine, so the solution is loaded once. Builds through Fuse take turns: parallel builds hit 0 locked-file errors in the benchmarks. Each git worktree gets its own engine, so agents in different worktrees never wait for each other.
  • Safe. If Fuse fails, the hook stays silent and the agent carries on. The stop hook sends the agent back at most once. Fuse never edits your code, runs locally and has no telemetry.
  • No configuration. fuse init is the only setup, and dotnet tool update works while Fuse runs.

What Fuse costs #

  • Memory. The engine keeps loaded projects in memory until it has been idle for 30 minutes: 256 MB on a 5-project solution and 795 MB on the 40-project Jellyfin, on runners with 16 GB of memory; the engine uses more on a machine with more memory (Benchmarks). Each git worktree runs its own engine.
  • A slow first check across projects. The first edit that affects other projects has to load them. On Jellyfin (40 projects) that took up to 92.2 s; the median signature edit took 85 ms.
  • One check at a time. Agents in the same repository wait for each other's checks.
  • Not a full build. Fuse checks C# only and picks tests by reading the code, so a few cases still need fuse build or fuse test --all. Limits lists them.
  • Two harnesses without build rewriting. In Cursor and GitHub Copilot CLI, the agent's own dotnet build runs unchanged and does not take turns with Fuse's builds.

Words these pages use #

The documentation uses each of these words for one thing only.

Working tree
Your files as they are on disk, including edits you have not committed.
HEAD
The commit you have checked out, in git's terms. Fuse compares the working tree with HEAD.
Introduced
An error is introduced when the working tree has it and HEAD does not. Fuse reports only introduced errors.
Declaration
Anything other code can refer to: a type, a method signature, a property, a field, a using directive. Changing a method's body is not a declaration change; renaming the method is.
Dependent project
A project that references another one, directly or through other projects. An app that references a library is a dependent project of that library.
Harness
The program an AI agent runs in, such as Claude Code, Cursor, Gemini CLI, Codex, GitHub Copilot CLI or OpenCode. A harness can run a command when something happens, such as after the agent edits a file.
Hook
A command a harness runs on such an event. Fuse registers three: post-edit (after an edit), pre-shell (before a shell command) and stop (before the agent finishes).
MCP server, MCP host
MCP, the Model Context Protocol, is a standard way for an agent to call tools. An MCP host is an application that runs MCP clients, such as VS Code agent mode. fuse mcp is an MCP server for hosts that run no hooks.
Engine
The background process, one per repository, that keeps the projects compiled and answers every command and hook. It starts on its own and exits after 30 idle minutes.
Affected tests
The tests that the changed code can reach, which are the tests that can fail because of the change.
Restore
Downloading a project's NuGet packages with dotnet restore (which dotnet build also does). Fuse needs restored projects and never restores on its own.

Requirements #

  • The .NET 10 SDK.
  • A git repository with at least one commit, because Fuse compares with HEAD. With no commit, every file counts as new and every error as introduced.
  • C# projects (.csproj). Visual Basic and F# projects are not checked.
  • Restored projects. When one is not restored, Fuse names the dotnet restore command to run.
  • Windows, Linux or macOS. CI builds and tests Fuse on all three; the published benchmarks come from GitHub Actions windows-latest runners.
