Fuse Documentation

All documentation pages

Fuse is a command-line tool for .NET repositories that tells an AI coding agent, right after each edit, which compiler errors that edit introduced and which tests it can break.

This page is for anyone new to Fuse: a developer setting it up for an agent, someone deciding whether to rely on it, or a contributor.

After reading it you know what Fuse does, the few words the rest of the documentation uses, and which page answers your question. To try it, go on to Getting started.

The problem Fuse solves #

A coding agent changes a repository in many small edits. After each one it needs to know whether the code still compiles and whether the tests still pass. Without Fuse it finds out the way a person does, by running dotnet build and dotnet test, and both are slow and noisy for this job:

  • A build does the whole job every time. dotnet build starts MSBuild, evaluates every project and compiles what changed. On the four repositories Fuse is measured on, the median build took between 1.14 s and 6.45 s (Results).
  • A build reports every error, not the agent's. If the repository already had errors before the agent started, the build lists them too, and the agent has to work out which ones its edit caused.
  • A test run runs everything. dotnet test runs every test in the solution and prints the passing ones as well as the failures, so the agent waits longer and reads more.

What Fuse does #

Fuse keeps the repository's C# projects compiled in memory, in a background process called the engine, and answers from it. An answer compares your files as they are on disk with the commit you have checked out, so it contains only what the current changes did.

  • Only introduced errors. Fuse reports an error only when your files have it and the checked-out commit does not. An error that was already there is never reported.
  • Breaks in other projects. When an edit changes a declaration, such as renaming a method, Fuse also checks the projects that depend on the edited one, and prints under each error the change that caused it.
  • Only the affected tests. fuse test runs the tests the change can reach and prints only the failures.
  • No commands to remember. fuse init registers hooks with the agent's harness, so Fuse runs after every edit and before the agent finishes, and in most harnesses replaces the agent's dotnet build and dotnet test.

In the measurements the median Fuse check took between 0.18 s and 0.87 s, 2.9x to 7.4x faster than the matching dotnet build. This is what happens after an agent edits a file:

  1. The agent edits a filefor example, it renames Calc.Add to Plus.
  2. The harness runs Fuse's hookwith the name of the edited file.
  3. The engine checks the changein the edited project and in every project that uses Add.
  4. The agent reads the resultthe two callers that broke, or nothing when the edit is clean.

Fuse never changes your code. It runs locally, has no telemetry, makes no network calls of its own, and reads no configuration.

Words these pages use #

The documentation uses each of these words for one thing only.

Working tree
Your files as they are on disk, including edits you have not committed.
HEAD
The commit you have checked out, in git's terms. Fuse compares the working tree with HEAD.
Introduced
An error is introduced when the working tree has it and HEAD does not. Fuse reports only introduced errors.
Declaration
Anything other code can refer to: a type, a method signature, a property, a field, a using directive. Changing a method's body is not a declaration change; renaming the method is.
Dependent project
A project that references another one, directly or through other projects. An app that references a library is a dependent project of that library.
Harness
The program an AI agent runs in, such as Claude Code, Cursor, Gemini CLI, Codex, GitHub Copilot CLI or OpenCode. A harness can run a command when something happens, such as after the agent edits a file.
Hook
A command a harness runs on such an event. Fuse registers three: post-edit (after an edit), pre-shell (before a shell command) and stop (before the agent finishes).
MCP server, MCP host
MCP, the Model Context Protocol, is a standard way for an agent to call tools. An MCP host is an application that runs MCP clients, such as VS Code agent mode. fuse mcp is an MCP server for hosts that run no hooks.
Engine
The background process, one per repository, that keeps the projects compiled and answers every command and hook. It starts on its own and exits after 30 idle minutes.
Affected tests
The tests that the changed code can reach, which are the tests that can fail because of the change.
Restore
Downloading a project's NuGet packages with dotnet restore (which dotnet build also does). Fuse needs restored projects and never restores on its own.

Requirements #

  • The .NET 10 SDK.
  • A git repository with at least one commit, because Fuse compares with HEAD. With no commit, every file counts as new and every error as introduced.
  • C# projects (.csproj). Visual Basic and F# projects are not checked.
  • Restored projects. When one is not restored, Fuse names the dotnet restore command to run.
  • Windows, Linux or macOS. CI builds and tests Fuse on all three; the published measurements come from one Windows machine.
