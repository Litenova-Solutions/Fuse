How Fuse Works

Fuse keeps your solution loaded in the background, the way an IDE does, and answers your agent's questions from it.

Hooks, Not Instructions

fuse init registers Fuse with the hooks each agent already has, so nothing depends on the agent remembering to call a tool.

  • After an edit, Fuse checks the edited files and reports only the errors that edit introduced.
  • Before a shell command, dotnet build and dotnet test are rewritten to fuse build and fuse test.
  • Before the agent finishes, Fuse checks every change once more and sends the agent back if the build is broken.

Agents without hooks, such as VS Code agent mode, use fuse mcp, which serves the same three operations as tools.

Checking an Edit

  1. Fuse holds two views of your solution: the files on disk, and the same files at your last commit.
  2. Each changed file is compiled in both views, and only the difference is reported. A line shift never counts as a new error.
  3. If only method bodies changed, the check ends there. If a declaration changed, Roslyn's symbol search finds every file that uses, implements or derives from it, in every dependent project, and those files are checked too.
  4. Compiler errors, warnings treated as errors, and analyzer rules set to error are reported. Only the analyzers that can report an error run.

Selecting Tests

  • A graph of which types refer to which is walked back from the changed code to the test classes that can reach it. This takes milliseconds.
  • When only a few test classes are reachable, the selection narrows to individual test methods.
  • Code that runs behind a host (controllers, handlers, hosted services) selects every test project that depends on the application.

Running Tests Without MSBuild

When only C# files changed since the last build, Fuse copies the test output to a private folder, compiles the changed assemblies from memory, and runs the tests there. Anything else, such as a project file or resource change, falls back to a normal dotnet test of the affected projects.

The Background Engine

  • One engine runs per repository. The first hook starts it, and it exits after 30 idle minutes.
  • Projects are evaluated at start and compiled only when a change touches them.
  • A file watcher keeps it current; a commit or branch switch moves the baseline.
  • A newer Fuse replaces an engine from an older version automatically.

Privacy and Footprint

  • Everything runs locally. Fuse has no telemetry and makes no network calls of its own.
  • It never edits your code and never runs dotnet restore on its own.
  • The only files it writes in your repository are the hook settings from fuse init.
  • In a repository without a .csproj, hooks return at once and no engine starts.
  • There are no settings and no environment variables.

Limits

  • C# only. Fuse needs the .NET 10 SDK and restored projects.
  • Custom MSBuild targets that change compiler inputs, and IL weaving, are invisible to a check; fuse build runs the real build.
  • Compilation-end analyzers do not run in a check.
  • Test selection is static, so tests that reach code only through reflection may not be selected.
  • Used day to day on Windows. Linux and macOS pass the automated tests.
