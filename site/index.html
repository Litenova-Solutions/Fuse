Fuse
Measured How it works GitHub

Compiler errors after every edit, for coding agents on .NET

Fuse keeps a warm Roslyn compilation of your repository. After each edit, your agent learns which errors that edit introduced, including breaks in projects that depend on it. When it runs dotnet test, only the tests the change can reach run.

$ dotnet tool install -g Fuse
$ cd your-repo
$ fuse init

That is the setup. Fuse works through your agent's hooks, so the agent needs no instructions and no tool to remember.

What the agent sees

An edit renames Calc.Add to Calc.Plus in a library. Before the agent moves on, the post-edit hook reports:

App/Program.cs(2,28): error CS1061: 'Calc' does not contain a definition for 'Add'
Lib.Tests/UnitTest1.cs(4,65): error CS1061: 'Calc' does not contain a definition for 'Add'
fuse: 2 new error(s) in 2 file(s) (App, Lib.Tests); Lib declarations changed, 2 dependent project(s) checked

An edit that introduces no error produces no output. Errors that were already there at the last commit are never reported.

When the agent runs dotnet test, Fuse runs the affected tests from freshly compiled assemblies and prints only failures:

FAILED Lib.Tests.CalcTests.Multiplies
  Assert.Equal() Failure: Values differ
  Expected: 6
  Actual:   7
fuse: 1 failed, 0 passed in 1.3 s; ran 1 test(s) affected by your changes out of 2

How it works

  • One engine per repository. The first hook or command starts it; it exits after 30 idle minutes. It evaluates every project with MSBuild and compiles a project only when a change touches it.
  • Checks compare with HEAD. Each changed file is bound in the working tree and at the last commit, and only the difference is reported. A changed declaration re-checks the files that use it, found with Roslyn's symbol search, in every dependent project.
  • Tests follow the code. Fuse walks from the changed code to the tests that can reach it, and runs them from a copy of the last build with the changed assemblies emitted in memory, skipping MSBuild when that is safe.
  • Nothing to configure. No settings file, no environment variables, nothing written inside the repository except the hook settings fuse init creates.

Works with

Claude Code, Cursor, Gemini CLI, Codex and GitHub Copilot CLI through their hooks, which fuse init registers. VS Code agent mode and any other MCP host use fuse mcp, which serves fuse_check, fuse_test and fuse_build. The Claude Code integration has been run end to end; the other hook adapters follow each harness's documented format.

Limits

  • C# only. Fuse needs the .NET 10 SDK and restored projects.
  • Build steps outside the compiler (custom targets that change inputs, IL weaving) are invisible to a check. fuse build runs the real build.
  • Test selection is static: tests that reach code only through reflection are selected when the walk reaches an application's host, not otherwise.
